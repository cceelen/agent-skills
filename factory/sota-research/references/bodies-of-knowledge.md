# Bodies of knowledge

A body of knowledge divides a whole field into knowledge areas. The research starts from it:
see step 1 of phase 2 in `procedure.md`. This file names where each one is. It does not hold
the content: read the document in each run, because its version changes.

| Field | Document | Issuer | Version when this row was read | Address | Row read on |
|---|---|---|---|---|---|
| software engineering | Guide to the Software Engineering Body of Knowledge (SWEBOK Guide) | IEEE Computer Society | 4.0a, 2025-09-25 | https://www.computer.org/education/bodies-of-knowledge/software-engineering | 2026-10-10 |

## How to read the SWEBOK Guide

- The guide is a PDF file behind a form on the page of the issuer. A reader cannot get it.
  Ask the owner to get the file and to give its path.
- Convert the file with `scripts/pdf.py`, and give the converted file to a file reader.
- The terms of the issuer permit individual use that is not commercial, and quotes of a
  reasonable length with the citation. They do not permit a copy for other persons. Thus keep
  the file and its converted text out of the repository, and write the evidence record in
  the words of this kit.
- If the owner cannot give the file, let a web reader read the page of the issuer for the
  list of the knowledge areas, and record in section 7 that the guide was not read.

## How to add a row

Add a row when an aspect belongs to a field that has no row. Read the page of the issuer in
the same turn, and write the version and the date that the page gives.
